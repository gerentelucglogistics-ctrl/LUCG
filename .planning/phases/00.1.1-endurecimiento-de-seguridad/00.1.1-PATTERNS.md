## Pattern Assignments

### `.claude/hooks/guardia-prod.sh` (middleware, stdin JSON → rc)

**Analog:** sí mismo. Mantener la estructura: extraer `command` con python3, `bloquear()` que sale con rc=2, `re()` con `grep -Eqi`, una regla por línea, `exit 0` al final.

**Cabecera y helpers** (líneas 1-6), copiar tal cual:
```bash
#!/usr/bin/env bash
# Hook PreToolUse (Bash): en modo YOLO el agente no publica en prod ni toca main.
# Bloquea solo acciones, no menciones: un grep o un commit que diga "prod" pasa.
cmd=$(python3 -c 'import sys,json;print(json.load(sys.stdin).get("tool_input",{}).get("command",""))' 2>/dev/null || true)
bloquear() { echo "Bloqueado en modo YOLO: $1. Prod y main los maneja el desarrollador principal a mano." >&2; exit 2; }
re() { printf '%s' "$cmd" | grep -Eqi -- "$1"; }
```

**Forma de una regla** (línea 10, la de `gh pr merge` se conserva):
```bash
re '(^|[;&|[:space:]])gh[[:space:]]+pr[[:space:]]+merge' && bloquear "fusionar PR a mano (usa 'just cierre-fase', que solo fusiona hacia dev)"
```
Cambios (RESEARCH Patrón 5): reemplazar el delimitador `(^|[;&|[:space:]])` por `(^|[;&|[:space:]'"(\`/])` en **todas** las reglas
(un `D='…'` al inicio evita repetirlo); añadir reglas para `gh api` de escritura (`-X`/`--method` ≠ GET **o** `-f/-F/--field/--raw-field/--input`)
sobre las rutas de la tabla del Patrón 5, `gh api graphql` con mutaciones, `curl|wget|http|xh` de escritura a `api.github.com`,
`gh (secret|variable) (set|delete|remove) … (-e|--env)[ =]?(prod|Production)`, `gh workflow run migrate … prod`, `gh workflow (enable|disable)`,
`gh run rerun … deploy-prod`, `gh pr review --approve`, `gh auth (token|switch|login|refresh)` y `--show-token`,
`security find-generic-password … gh:github.com`, y ampliar `git push` (`refs/heads/main`, `+…:main`, `--all`, `--mirror`, `--delete`).
Las reglas actuales de `git push` (líneas 8-9, 16) y de infra (13-15) se mantienen.
Mensaje de `bloquear` y cabecera: actualizar para decir que dev lo fusiona `fusionar-dev.sh` (D-21).
Orden obligatorio (D-18a, Pitfall 5): el commit que cambia este archivo va **después** de la tarea de ajustes de prod con `github-lucg`.

### `scripts/fusionar-dev.sh` (utility, gh request-response)

**Analog:** `scripts/cierre-fase.sh`.

**Cabecera y modo estricto** (líneas 1-6):
```bash
#!/usr/bin/env bash
# Cierre de fase: push, PR a dev, CI (checks requeridos), merge, despliegue a dev (incluye pruebas en dev).
# Uso: ./scripts/cierre-fase.sh "H1 / 1.2 Importador IMILE"
set -euo pipefail
BASE=dev
```
Argumento obligatorio al estilo de `vercel-preview-url.sh:6`: `PR="${1:?uso: fusionar-dev.sh <PR>}"`.

**Verificación de base con gh -q y salida temprana** (línea 23):
```bash
[ "$(gh pr view "$PR" --json baseRefName -q .baseRefName)" = "$BASE" ] || { echo "El PR #${PR} no apunta a ${BASE}; no se fusiona"; exit 1; }
```
Extender con una sola llamada `gh pr view "$PR" --json baseRefName,author,headRefOid,isCrossRepository,state` (RESEARCH Patrón 8) y comprobar `author.login == $BOT`, `!isCrossRepository`, `state == OPEN`; guardar `headRefOid` como `SHA` antes de mirar los checks.

**Espera de checks** (líneas 28-32), reutilizar el bucle de aparición:
```bash
for _ in $(seq 1 30); do
  [ "$(gh pr checks "$PR" --required --json name -q length 2>/dev/null || echo 0)" -gt 0 ] && break
  sleep 5
done
gh pr checks "$PR" --required --watch --fail-fast
```
Luego `gh pr checks "$PR" --json name,bucket` y exigir `api`, `web`, `e2e-preview`, `visual-sitio` (y `guardia` cuando exista) con `bucket ∈ {pass, skipping}` (D-14). `--watch` sin `--required` devuelve rc=8 con pendientes: tolerarlo.

**Fusión** (línea 35), endurecida:
```bash
gh pr merge "$PR" --squash --delete-branch          # actual
gh pr merge "$PR" --squash --delete-branch --match-head-commit "$SHA"   # nuevo
```
Mensajes en español, sin imprimir tokens. Pitfall 10: tras `--delete-branch` la copia local queda en `dev`; avisarlo en la salida.
