### `apps/api/app/api/v1/yo.py` (route, request-response con RLS) — nuevo

**Analog:** forma del router en `health.py` L1-9; dependencias en `app/core/auth.py` L31-45 y `app/core/db.py` L13-20.

Router (copiar de `health.py`):
```python
from fastapi import APIRouter
router = APIRouter(tags=["salud"])   # o tags=["identidad"]
```
Sesión con contexto que hay que envolver como dependencia (`db.py` L13-20):
```python
def sesion_con_contexto(principal: Principal) -> Iterator[Session]:
    """Abre una transacción y fija el contexto de RLS (app.set_contexto) para el usuario autenticado."""
    with SessionLocal() as s, s.begin():
        s.execute(
            text("select app.set_contexto(:tipo, :org, :roles)"),
            {"tipo": principal.org_tipo, "org": principal.org_id, "roles": principal.roles},
        )
        yield s
```
Agregar en `db.py` (la usan `yo.py` y las rutas futuras):
```python
def sesion_dep(p: Annotated[Principal, Depends(principal_actual)]) -> Iterator[Session]:
    yield from sesion_con_contexto(p)
```
Cuerpo del endpoint (RESEARCH Pattern 3). Las funciones SQL existen en `0001_base.sql` L26 (`app.org_tipo()`) y L31 (`app.es_interno()`):
```python
@router.get("/yo")
def yo(p: Annotated[Principal, Depends(principal_actual)],
       s: Annotated[Session, Depends(sesion_dep)]) -> dict[str, object]:
    fila = s.execute(text("select current_user, app.org_tipo(), app.es_interno()")).one()
    return {"usuario": p.user_id, "roles": p.roles, "rol_db": fila[0], "org_tipo": fila[1], "interno": fila[2]}
```
Ojo: la importación circular `db.py` → `auth.py` ya existe (`db.py` L6 importa `Principal`). `sesion_dep` va en `db.py` y no en `auth.py`. Conviene un modelo Pydantic de respuesta (`YoOut`) para que el cliente generado quede tipado (ASVS V5).

### `apps/api/app/api/v1/diagnostico.py` (route, auth + encolado) — nuevo

**Analog:** `app/core/auth.py::requiere_rol` L48-54 y `app/jobs/worker.py` L9-11.

Guardia por rol (ya existe; el `type: ignore[no-untyped-def]` se puede tipar como `Callable[..., Principal]`):
```python
def requiere_rol(*roles: str):  # type: ignore[no-untyped-def]
    def dep(p: Annotated[Principal, Depends(principal_actual)]) -> Principal:
        if p.org_tipo == "lucg" and ("superadministrador" in p.roles or any(r in p.roles for r in roles)):
            return p
        raise HTTPException(status.HTTP_403_FORBIDDEN, "Sin permiso")

    return dep
```
Uso en el router: `router = APIRouter(prefix="/diagnostico", tags=["diagnostico"], dependencies=[Depends(requiere_rol("superadministrador"))])`. Así **todo** el módulo exige auth, y ninguna ruta queda abierta en prod (CONTEXT, Discretion).
Endpoints (RESEARCH Pattern 4):
- `POST /diagnostico/ping` → `job_id = await ping.defer_async()` → `{"job_id": job_id}`
- `GET /diagnostico/jobs/{job_id}` (`job_id: int`) → `await worker_app.job_manager.get_job_status_async(job_id)`
- `POST /diagnostico/error` → `raise RuntimeError("Error de prueba Sentry (diagnóstico)")`. Así Sentry recibe un error no manejado (D-15).
Importar la tarea del módulo worker: `from app.jobs.worker import app as worker_app, ping`.

## Shared Patterns

### Autenticación y contexto RLS
**Source:** `apps/api/app/core/auth.py` L31-54 + `apps/api/app/core/db.py` L13-20
**Apply to:** `yo.py`, `diagnostico.py` y toda ruta futura que toque `app.*`
- Identidad: `Annotated[Principal, Depends(principal_actual)]`. Autorización: `Depends(requiere_rol(...))`. Datos: `Annotated[Session, Depends(sesion_dep)]`. El `set_contexto` corre siempre dentro de `s.begin()` (regla 1).
- Errores: `HTTPException(status.HTTP_401_UNAUTHORIZED, "Falta el token" | "Token inválido")` y `HTTP_403_FORBIDDEN, "Sin permiso"`, con mensajes en español.

### Errores de dominio
**Source:** `apps/api/app/core/errors.py` L5-20 (`ErrorDominio` → `application/problem+json`, `type: urn:lucg:error:{codigo}`)
**Apply to:** cualquier error de negocio. En 0.1 casi no se usa. El error de prueba de Sentry **no** debe ser `ErrorDominio`, porque ese error se maneja y no llega a Sentry como excepción no manejada.

### Configuración por entorno
**Source:** `apps/api/app/core/config.py` L7-31 (`Field(alias="MAYUSCULAS")`, `get_settings()` con `@lru_cache`)
**Apply to:** toda variable nueva (`CORS_ORIGIN_REGEX`, versión). Documentarla en `apps/api/.env.example` y en `/.env.example`. Para el frontend, las variables `VITE_*` se declaran en `src/vite-env.d.ts` (`interface ImportMetaEnv`).

### Sentry con environment + release
**Source:** `apps/api/app/main.py` L10-11; `apps/web/src/main.tsx` L13-15; `apps/driver/src/main.tsx` L7-9
```ts
if (import.meta.env.VITE_SENTRY_DSN) {
  Sentry.init({ dsn: import.meta.env.VITE_SENTRY_DSN, environment: import.meta.env.VITE_APP_ENV, release: __APP_VERSION__ });
}
```
**Apply to:** las tres apps. La release es el SHA completo en los tres casos, para que coincida con `getsentry/action-release` `version: ${{ github.sha }}`. Sin `sendDefaultPii` en el navegador. `data_collection` restrictivo en la API.

### Cliente API tipado desde el navegador
**Source:** `packages/api-client/src/index.ts` L5-15 + `apps/web/src/lib.ts` L4-8
**Apply to:** `Login.tsx`, `Consola.tsx` y la PWA. Nunca `fetch` directo a la API (regla 5). Después de agregar `/yo` y `/diagnostico/*`, regenerar `openapi.json` + `schema.ts` (`just gen-client`, o el comando de `ci.yml` L36). CI comprueba que `schema.ts` no tenga diff (L52-53).
