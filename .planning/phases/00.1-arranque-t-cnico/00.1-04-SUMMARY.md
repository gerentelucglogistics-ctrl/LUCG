# Phase 00.1 Plan 04: Diagnóstico, Sentry 3 e imagen Railway Summary

La API expone un job de prueba del worker y un error de prueba de Sentry, ambos solo para superadministrador; Sentry 3 recoge datos de forma restrictiva; la misma imagen sirve api y worker en Railway; y el cliente tipado incluye las rutas nuevas.

## Tareas

1. **Tarea 1** (26630c7): `diagnostico.py` (ping, estado de job, error), router, lifespan con `worker_app.open_async()`, CORS con `allow_origin_regex`, `release=version.sha_completo()`, fixture `client` con lifespan. 12 pruebas nuevas (401 y 403 en las 3 rutas, error propagado, ping encolado con estado `todo`, worker procesa ping hasta `succeeded`).
2. **Tarea 2** (2ae7979): Dockerfile (sin fallback, `COPY VERSION*`, `${PORT:-8000}`, proxy headers), `railway.api.json` (healthcheck `/api/v1/health`, us-east4) y `railway.worker.json` (startCommand procrastinate, restart ALWAYS), `.env.example`, openapi + schema.ts regenerados.
